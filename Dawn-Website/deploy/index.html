DAWN / OVERVIEW

Overview

What Dawn is, where it runs and how its version numbers line up.

What Dawn is

Dawn is a script executor for Roblox on Windows. The desktop app (the Dawn window) is the control surface: attach, editor, script hub, terminal, settings. The actual execution environment loads inside the Roblox client through a module that the bundled injector places on attach.

The pair talks over a local bridge: the editor sends code, the client runs it, and Roblox output flows back into the terminal tab.

Version identifiers

IdentifierValueMeaning
Windows statusworkingWhether the current executor is verified against the current Roblox version. Shown live on the Home tab.
Roblox versionliveIdeal Roblox support window vs. your currently installed client; Dawn warns when the client drifts.

After a Roblox update, check the Home tab first — Dawn reports the exact mismatch instead of failing silently mid-attach.

Platform requirements

  • Windows 10 or 11, 64-bit (Windows 11 is the test target).
  • .NET Framework 4.8 runtime — ships with all current Windows installs.
  • Any Roblox client version inside the current support window.
note Install size is small and the whole thing lives in one folder — %LOCALAPPDATA%\Dawn by default. Nothing writes outside that folder except shortcuts and the uninstall registry entry.

DAWN / INSTALLATION

Installation

One exe does the whole job: install, repair, uninstall — no dependencies to gather first.

Get the bootstrapper

Grab the current release's Bootstrapper.install.exe (about 11 MB) from the Dawn Discord server — it's the only file you need, everything else is packed inside it.

Download on Discord Bootstrapper.install.exe · installer + executor + module, one file
notice Windows SmartScreen may ask about the exe on first run because it isn't signed with a store certificate. Choose More info → Run anyway.

Verify the download (SHA-256)

Drop Bootstrapper.install.exe here
or — the hash is computed locally in your browser and checked against the current release automatically.

Prefer the terminal? No extra software needed, Windows has the tools built in:

powershell
Get-FileHash "C:\path\to\Bootstrapper.install.exe" -Algorithm SHA256
cmd
certutil -hashfile "C:\path\to\Bootstrapper.install.exe" SHA256

Either command prints the SHA-256 digest. Compare it against the current release:

current release · sha-256
d58fcc6a93701a390934dff63671d3bdf1ed4fd3d0a178adabacbb9f28d824ed
note Replace C:\path\to\Bootstrapper.install.exe with the actual path to your download. A mismatch means the file changed in transit — grab it again from the Discord server.

The install flow

  1. Run Bootstrapper.install.exe. Dawn's own installer window opens — no separate wizard theme.
  2. Install to shows the default folder, %LOCALAPPDATA%\Dawn. Use Browse to pick another spot and the button flips between Install and Repair based on what's already in the target folder.
  3. Tick what you want up front:
    • Defender exclusions — adds the install folder as an antivirus exclusion through one UAC prompt. Recommended: it stops the module from being scanned or quarantined after install. Declining the prompt simply skips exclusions.
    • Desktop shortcut — Dawn.lnk plus an Uninstall Dawn.lnk.
    • Launch when done — opens Dawn immediately.
  4. Install extracts the payload, places an Uninstall Dawn.exe inside the folder and registers Dawn in Settings → Apps → Installed apps so it uninstalls like any store-less app.

Over an existing install the same exe performs a repair: files refresh in place, running Dawn blocks it politely (close Dawn first — nothing is force-killed).

Silent installs

The bootstrapper takes flags for scripting and automation; silent installs touch nothing outside the folder unless asked:

cmd / powershell
Bootstrapper.install.exe --verify "C:\path\to\test-dir"   &:: unpack + status lines, zero side effects
Bootstrapper.install.exe --install "C:\My\Dawn"           &:: install, nothing extra
Bootstrapper.install.exe --install "C:\My\Dawn" --shortcuts --auto-launch --defender
Bootstrapper.install.exe --launch "C:\My\Dawn"            &:: start Dawn.exe from a path
Bootstrapper.install.exe --uninstall "C:\My\Dawn"         &:: silent payload removal

First launch

Dawn opens on the Home tab: executor version, API version, Roblox support and Windows status — all live. If a key panel appears on first run, that flow lives there too.

DAWN / GETTING STARTED

Getting started

Open Dawn, open Roblox, execute your first script — three moves.

Attach

Start Roblox first, then Dawn (order doesn't matter for the client, but attach needs an alive Roblox). On the Home tab, use Attach.

  • The client list reads the running Roblox processes — pick or auto-select when there's only one.
  • If you bound Quick Attach, attach works from anywhere — no window focus needed.
  • Attach is per client, one at a time: one Dawn module per Roblox instance.
note Attach grabs the first Roblox it finds. Second windows opened after attach aren't picked up automatically — attach while exactly one client is running if you need precision.

Your first script

Open the editor, drop one line in and execute:

luau
-- verify the environment is alive where you expect it
identifyexecutor()
-- classic
print("hello from Dawn")

Execute with Ctrl + Enter in the editor, the Execute button, or your global Execute hotkey. Roblox's responses and prints land in the terminal tab, streamed live.

Where scripts live

Dawn reads three folders under its install root:

FolderRole
Scripts\Your script library — browse and run them through the UI.
AutoExec\Drop scripts here that should run without you opening a tab every session. See AutoExec.
Workspace\Working files and folders the editor trusts blindly.

DAWN / SCRIPT EDITOR

Script editor

Tabs, restoration and the moves that get code into the client.

Tabs

The editor works tab-first. Open as many tabs as you need, rename in place, close independently. Tabs survive the app closing: after a restart they come back with their code, so losing a slowly-built script to a reboot isn't a thing.

Executing

  • Ctrl + Enter — execute the focused tab. This is also Dawn's default global Execute hotkey, so it triggers with the same combo even when the window isn't focused — a master toggle in Settings → Hotkeys turns that off.
  • The Execute button — runs the active tab.

Saving

Ctrl + S saves the current tab to disk. Editor behaviour — autosave intervals and how the editor handles untitled buffers — sits in Settings → Editor; file browse behaviour (how folders and file open/save dialogs behave) lives under Settings → Explorer.

Fetch a script from URL

Paste a raw script URL into the browse bar and Dawn pulls the body straight into a tab. Great for hosted gists and raw files — no clipboard trip.

GitHub backup

The editor also carries GitHub integration: point it at a repo with your token and push your scripts up, browse repos and restore files from them. Token entry lives inside the editor's GitHub panel — it stays local to your machine.

Folders Dawn trusts

All file operations are rooted in the install folder layout: Scripts\, AutoExec\, Workspace\. Organize those three freely — the explorer shows what's on disk in real time.

tip Keep heavy loops out of tabs you execute from hotkeys. A runaway while true executes exactly where it was fired from — the Kill Roblox hotkey is there for those exact moments.

DAWN / HOTKEYS

Hotkeys

Everything triggerable in Dawn has a remappable combo under Settings → Hotkeys.

The master switch

Enabled Hotkeys gates the whole system. Off means: no global triggers fire anywhere, editor-local shortcuts still work.

The three commands

CommandDefaultWhat it does
Execute ScriptCtrl + EnterRuns the focused script — works globally, from any app.
Kill Robloxyour choiceCloses the attached Roblox instantly. The panic button.
Quick Attachyour choiceRun-time attach with zero clicks — bind and dump them before you can say attach.

Remapping

  1. Open Settings → Hotkeys.
  2. Click the combo field you want to change and press the new combination — the field records what you press.
  3. The binding is live immediately; settings persist between sessions.

Dawn deliberately divides hotkeys by behaviour rather than typing "Ctrl is always X": an unattached window shares execution across tabs and never fights with Roblox overlays.

heads up While Enabled Hotkeys is on, the Kill Roblox combo works system-wide — think before choosing a combo you tap by accident.

DAWN / CONSOLE OUTPUT

Console output

Roblox's own print, warn and error output — surfaced inside Dawn, live.

The terminal tab

When Dawn is attached, everything the client prints lands in Dawn's Terminal tab stream-fresh. Errors from a failed Ctrl + Enter show up here in-copy, which makes "why did this not run" a five-second read instead of a blind retry loop.

Console redirection

Console redirection routes Roblox's output streams into Dawn with per-stream control — you choose when it belongs in the terminal and when Roblox keeps its normal console. The toggle and its per-stream entries live in Settings.

  • Useful for heavier sessions where stdout would flood the terminal.
  • Turning redirection off never stops Dawn from showing her own result progress — it purely controls client stream capture.

dawn_debug.log

App-side diagnostics land in dawn_debug.log inside the install folder. Attach trouble, config oddities, stream failures — if the terminal looks too quiet, the log has the app-side truth. It stays in place from run to run; the uninstaller clears it with the payload.

DAWN / SCRIPT HUB

Script hub

Browse, search and run library scripts without touching a file dialog.

Search

The hub's search input filters the library by name as you type — press Enter to run the search and see the results grid. From there it's open-in-editor or run-in-place.

Categories

Scripts sort by category so the pile stays navigable — pick a category, browse normally, search inside it. Running a script loads it into the current client like anything executed from the editor, so the same terminal output shows the results.

note Library scripts are third-party content: read what a script does before you run it. Dawn runs it into the attached client exactly as the author wrote it.

DAWN / AUTOEXEC

AutoExec

Scripts that load themselves after attach — configuration as code, no clicks.

How it works

Any .lua / .luau file you drop into the AutoExec\ folder of the install root gets queued per attach. The intended routine:

  1. Attach to a Roblox client.
  2. Dawn walks AutoExec\ and runs each script on its own, in name order.
  3. Output shows up in the terminal like any other execution.

What people use it for

  • Environment guards that bring getgenv() configuration tables back each session.
  • Per-game or per-account configuration that resets on every login otherwise.
  • Tiny wrappers that make library scripts one save away from running.
AutoExec\my-config.luau
-- written by you, loaded by Dawn on attach
local cfg = getgenv()
cfg.selected = "primary"
cfg.verbose  = true
print("[autoexec] config loaded")
heads up AutoExec runs whatever is in the folder — treat it like shell startup scripts. Only keep files you wrote or reviewed.

DAWN / API REFERENCE

API reference

The function surface the Dawn module loads into the Roblox client, as executed by identifyexecutor().

Everything below lives in the client's Lua environment after attach — the same globals scripts use. Dawn's own app behaviour (hotkeys, file dialogs, settings) is not part of this API.

getgenv

getgenv() → table — the shared environment table. Value written here is visible to every script that runs after it, across tabs and across AutoExec. Use it for cross-script configuration instead of touching Roblox globals.

luau
local env = getgenv()
env.theme    = "midnight"
env.retries  = 3
print(getgenv().retries)   --> 3, everywhere

getreg

getreg() → table — the Lua registry, the hidden table behind values the engine keeps to itself. Reach in deliberately; it's an advanced surface and a bad write there takes the whole client with it.

debug.getregistry

debug.getregistry() → table — the same registry under the debug namespace, when a script already calls for it there. One registry, two spellings.

cloneref / clonereference

cloneref(instance) → instance — hands out a duplicate reference to an Instance that scripts can keep in their own scope. The alias clonereference() does the same thing; both exist because the community uses both spellings.

luau
local hl = cloneref(game:GetService("CoreGui"))
-- hl behaves like CoreGui but is your reference

hookfunction

hookfunction(old, new) → function — swaps a callable's implementation. Returns the original so you can restore it. If a script now passes values through a function you can grab, you can shim it:

luau
local old
old = hookfunction(someFn, function(a, b)
print("hooked:", a, b)
return old(a, b)              -- call through to the original
end)
note The hook must match callable shapes it can genuinely displace — mismatched input gets reported by the error text (hookfunction: incompatible closu…) instead of silently no-op'ing.

firesignal

firesignal(signal [, ...]) — fires a signal manually, as if the event dispatching stayed on. Takes the signal's connected callbacks with given arguments.

luau
firesignal(someRemote.OnClientEvent, "payload")

identifyexecutor

identifyexecutor() → string — the executor's own name badge; scripts that check the runtime read it first:

luau
if identifyexecutor() == "Dawn" then
-- Dawn-specific behaviour can go here
end

The engine underneath

Dawn's module rides a full Luau environment, so everything the engine normally offers keeps working: task, coroutine, string library methods, pcall/xpcall variance and the standard Instance model are all intact — the Dawn surface above is what gets added on top, not what replaces the base.

DAWN / UNINSTALL

Uninstall

Three ways out, all gentle, none of them kill a running app.

The three ways

01 · windows

Apps & features

Dawn is registered there on install. Hit Uninstall and Windows launches the folder's uninstaller with the right target pre-filled.

02 · desktop

Uninstall Dawn

Double-click Uninstall Dawn.exe (install folder or the desktop pairing). It shows Dawn's own uninstaller window, locked to its folder.

03 · silent

Command line

Bootstrapper.install.exe --uninstall "path" — no window, nothing killed, same sweep.

What gets removed, what stays

  • Removed: every installed file — app, tools, module twins, scripts stub — plus both desktop shortcuts, the Apps & features listing and runtime debris like dawn_debug.log. Empty subfolders get pruned too.
  • Kept: tools\auth_config.json, tools\pool_config.json, tools\discord_rpc.json — your key material and settings survive reinstall, a fresh install picks them up.
  • Kept: the folder itself (the root isn't deleted — uninstall leaves three config files there by design, so wipe it yourself if you want the folder gone).

If Dawn or Roblox is running

Uninstall refuses politely with Dawn.exe is running — close Dawn first rather than killing anything while it's writing. Close it, rerun, done. The same rule covers the installer's repair mode.

note Uninstalling Dawn does not touch your Roblox install, account or local Roblox settings — it only dismantles what the bootstrapper put down.

DAWN / TROUBLESHOOTING

Troubleshooting

The common walls, in the order they usually appear.

SymptomWhat it meansMove
Attach does nothingNo live client was found to attach to.Open Roblox first. Close extra Roblox instances — attach picks the first one it scans past.
Dawn.exe is running — close Dawn firstRepair / uninstall while the app is open.Close Dawn and rerun the installer. Deliberate — nothing is force-killed.
Scripts stop responding after a whileThe module lost the bridge from a client exit — Roblox may have been relaunched outside Dawn.Reattach. Fresh relaunches of Roblox need a fresh attach each time by design.
Defender quarantined the moduleReal-time scan removed Module.dll after attach.Run the bootstrapper again and accept the Defender exclusions prompt (UAC), then repair to restage the files.
Terminal shows nothing after executeOutput redirection is off, or attach went stale.Check console redirection, then reattach; dawn_debug.log in the install folder has app-side detail.
UI opens but pages render blankRuntime rendering layer missing (rare on Win11, seen on stripped Win10 installs).Run the Microsoft Evergreen runtime installer once and relaunch Dawn.
Install stalls on a fileAntivirus briefly scanning while extraction writes.The bootstrapper already tolerates this (ties a warn line instead of failing). If files keep missing, exclude the folder and repair once.

Diagnostics

  • dawn_debug.log — app-side trail (attach attempts, settings apply, stream faults).
  • Home tab — live executor / API / Roblox version checks; version drift is the most common post-update hiccup.
  • --verify — unpack the bootstrapper to a scratch dir to prove the payload is intact: Bootstrapper.install.exe --verify "%TEMP%\dawn-check".
order After any Roblox client update, assume nothing and re-check the Home tab before attaching. Version-sensitive issues heal themselves in Dawn's next release, not on the client you installed five days ago.

DAWN / FAQ

FAQ

Short answers to the things people actually ask.

Do I need a key?

If the Home tab shows a key panel, that's the flow — and the key material is stored locally at tools\auth_config.json. Uninstalling keeps that file, so you won't re-key after a repair or reinstall.

Does it run on Windows 10?

The install runs — Windows 11 is the correctness target. Windows 10 boxes in generally-shapeless states sometimes need the Microsoft Evergreen runtime installed once; after that, identical behavior.

Can I run it on two Roblox windows?

One Dawn module per Roblox client. Attach picks the first client it sees; second-and-later instances need their own attach session with the usual ordering discipline.

Will updating Dawn lose my settings?

No — settings and configs ride in tools\*.json, and both install (repair) and uninstall are built to leave them in place.

Why does antivirus flag the module?

Generic heuristics catch executor modules at compile, no matter the author. The Defender exclusions step in the installer (one UAC prompt, excludes only the install folder) is the whole cure. Third-party AV exclusion lists also work if you'd add the folder yourself.

What does uninstalling break?

Nothing outside Dawn's own footprint. It removes Dawn's files, shortcuts and registration, keeps your three configs, and stops short of touching Roblox, your accounts or anything the bootstrapper didn't install.

Where are my scripts?

Scripts\ in the install root, editable via any editor, browsable from Dawn. AutoExec\ is the always-run cousin — see AutoExec.

Where do I report something?

The Discord invite in the app (Home tab) is the fastest line to version chatter, bugs and fixes. Bring your dawn_debug.log excerpt — it short-circuits the first three questions.
